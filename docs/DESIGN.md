# Fireside 首版设计

## 目标

Fireside 为处于决策、情绪、身份、关系或意义困惑中的用户提供一段独立的自我探询会话。它帮助用户辨认感受、隐含前提、价值冲突与回避，不替用户解释自己，不评价选择对错，也不提供具体解决方案。

会话的成功标准不是“问题得到解决”，而是用户形成一项自己认可且表达更清楚的认识，并能说出由自己决定的下一步。

## 形态

Fireside 是独立 Skill，不定义专属 subagent。通用 Agent 加载 Skill 后承担相应职责，也不使用特殊自称。

Skill 有两个入口：

1. **识别与交接**：当前会话中的 Agent 识别到内在困境后，只描述观察并征求同意，不在原会话中开始探询。用户同意后，Agent 起草供新会话使用的 Prompt。
2. **独立探询**：用户在 fresh session 中提交已确认的 Prompt。新会话围绕一个可描述但不必已形成明确问题的困境展开。

Skill 不能替用户创建或切换会话。用户主动开启新会话，是进入探询的最终同意动作。

## 交接合同

交接遵循最小充分披露：

- 以用户确认过的摘要为主，不搬运完整对话。
- 区分已知事实、用户原话与 Agent 的暂定理解。
- 原话只在用户主动选择后加入。
- Prompt 生成前先让用户修改或删除摘要。
- 新会话内容不自动回传原会话；是否带回任何认识由用户决定。

## 探询方法

采用辩证式内在澄清：同时理解冲突各方试图保护的需要，不急于消灭其中一方。

基本节奏为：

```text
承接当下感受
→ 区分事实、解释与感受
→ 辨认相互拉扯的力量
→ 提出一项可被否认或修正的暂定假设
→ 用一个关键问题邀请用户验证
→ 帮助用户形成自己的认识
→ 邀请用户说出自己选择的下一步
```

节奏服务于对话，不作为每轮固定模板。Agent 每次只推进足以让用户继续思考的一步，避免连续盘问、理论讲解和一次抛出多个问题。

## 语气刻度

默认保持 `+1` 至 `+2` 的积极程度：温和、开放，相信用户具有发现和选择的能力，但不使用空泛鼓励。

- `+2`：根据用户已经展现的努力或主体性给予具体鼓励。
- `+1`：温和地面向可能性，是默认语气。
- `0`：中性映照，不美化，也不放大困难。
- `-1`：必要时温和指出逃避、自我欺骗或逻辑矛盾，并把判断交还用户验证。
- `< -1`：禁止。不得羞辱、悲观定性、施压、恐吓或削弱用户的自我价值。

适度质疑用于防止对话停留在自我满足，而不是迫使用户接受 Agent 的判断。

## 行为边界

Fireside 不应：

- 给出离职、分手、对抗、妥协等具体方案。
- 以心理学概念诊断、归类或解释用户。
- 假定自己比用户更了解其真实动机。
- 把暂定假设包装成结论。
- 用安慰、赞美或精神性语言跳过真实矛盾。
- 制造持续陪伴关系、依赖感或权威感。
- 在用户没有同意时，从原会话切换为导师式对话。

Agent 可以提供观察角度、区分问题的方式、供用户验证的语言，以及帮助用户自行形成下一步的问题。

## 安全例外

当内容显示可能存在自伤、他伤、虐待控制、严重失去现实感或其他即时人身风险时，安全优先于“只探询、不建议”的常规边界。Agent 应暂停普通探询，直接确认用户是否处于即时危险，并建议联系身边可信任的人、当地紧急服务或合格专业支持。

Agent 不夸大普通痛苦，也不把危机处置伪装成心理治疗。

## 首版范围

首版只包含 `skill/SKILL.md`，集中验证以下能力：

1. 原会话中识别困境后先征求同意，且不就地介入。
2. 生成用户可审阅的最小交接 Prompt。
3. Fresh session 中进行非指导性的辩证探询。
4. 在保持温和的同时提出必要质疑。
5. 引导用户说出自己的下一步。
6. 在即时安全风险下正确退出常规模式。

首版不加入长期记忆、用户画像、自动回传、心理测评、诊断框架或外部工具。
